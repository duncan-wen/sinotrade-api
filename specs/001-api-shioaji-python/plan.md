## 總結
本計畫旨在實作一個後端 API，該 API 封裝了 `shioaji` Python 函式庫，提供一個統一的介面來獲取多種金融商品（股票、期貨、選擇權）的即時報價，並為特定使用者角色提供模擬下單功能。API 將使用 FastAPI 框架開發，並透過 API 金鑰進行驗證。

**語言/版本**: Python 3.11+
**執行環境**: uv 虛擬環境

**專案類型**: 單一專案 (API)
**效能目標**: 系統延遲 < 50毫秒 (不含上游 API 延遲)
**限制**: 即時資料新鮮度在 1 秒內。
**規模/範圍**: 原型級別，支援少量並發使用者。

## 階段 0: 綱要與研究
1. **從上面的技術背景中提取未知數**:
   - 主要的未知數是 `shioaji` 對於不同類型的金融商品（股票、期貨、選擇權）返回的確切物件結構。雖然該函式庫力求一致性，但我們需要驗證每種類型的合約。

2. **產生並分派研究代理**:
   - 任務: "研究並記錄 `shioaji` 對於股票、期貨和選擇權的報價和訂單物件結構。"

3. **在 `research.md` 中整合研究結果**:
   - 決策: 記錄資料結構。
   - 理由: 確保我們的模型能正確對應到上游 API。
   - 考慮過的替代方案: 不適用

**輸出**: `research.md`，其中定義了 Shioaji 物件結構。

## 階段 1: 設計與合約
*先決條件: research.md 已完成*

1. **從功能規格書中提取實體** → `data-model.md`:
   - 定義 `FinancialInstrument`, `Quote`, `APIUser`, `SimulatedOrder` 的 Pydantic 模型。

2. **從功能需求中產生 API 合約**:
   - 在 FastAPI 中為以下端點定義 OpenAPI 綱要:
     - `GET /quote/{symbol}`: 獲取金融商品的報價。
     - `POST /order`: 下一個模擬訂單 (針對 `trader` 角色)。
   - 綱要將由 FastAPI 自動產生，並可在 `/docs` 查閱。

3. **從合約中產生合約測試**:
   - 建立 `tests/contract/test_api.py`。
   - 編寫測試，用有效和無效的資料呼叫 API 端點，並斷言回應狀態碼和綱要。

4. **從使用者故事中提取測試情境**:
   - 建立 `tests/integration/test_scenarios.py`。
   - 實作遵循使用者故事的整合測試 (例如，`viewer` 可以獲取報價，`trader` 可以下單)。

5. **增量更新代理檔案**:
   - 此工作流程不適用。

**輸出**: `data-model.md`, 失敗的合約和整合測試。
